# Architecture & Collaboration Audit — 2026-07-03

*Full audit of the Reality repository after a multi-agent divergence incident.
Written by the Claude Code session in `~/Fable`. Read alongside [AGENTS.md](../AGENTS.md).*

---

## 1. Executive summary

Reality is worked by **more than one AI agent at the same time**, plus an
automated PR pipeline. That is a feature, not a bug — but the repo was **not
configured** for it. On 2026-07-03 the `main` branch **diverged**: one agent
committed the "cooking" feature to a local `main` without pushing, while the PR
pipeline merged "weather" (#16) to `origin/main`. Neither copy was complete, and
a naive merge of the stale feature branches would have **deleted 500+ lines**.

The incident was resolved without data loss (3-way merge, both features kept,
92 tests green, deployed). This audit records **why it happened** and installs
**enforceable rules** so it cannot recur.

**Root cause in one line:** multiple working copies + agents committing directly
to an **unprotected** `main`, with **no branch-up-to-date gate** on merges.

## 3. Root-cause analysis

| # | Cause | Consequence |
|---|---|---|
| C1 | **Multiple checkouts on `main`**, agents committing locally | Local `main` forked from `origin/main` |
| C2 | **`main` unprotected** | Direct pushes & force-push possible; no gate stopped the fork |
| C3 | **No "branch must be up to date before merge" rule** | Stale branches merge-able → would delete newer code |
| C4 | **Auto-delete off** | Merged branches linger and masquerade as "unmerged" |
| C5 | **Orphaned uncommitted WIP** (the kitchen feature sat uncommitted in `~/Fable`) | Looked like "files modified/missing"; nearly lost |
| C6 | **No agent-ownership doc** | No rule said "one agent per checkout, one branch per agent" |

---

## 4. Risk register (pre-remediation)

| Severity | Risk | Mitigation (below) |
|---|---|---|
| **CRITICAL** | Divergent `main` → lost features / forced history rewrite | R1 branch protection, R2 one canonical checkout |
| **HIGH** | Stale branch merged → silent regression (−500 lines) | R1 strict up-to-date gate |
| **HIGH** | Orphaned uncommitted WIP lost on `git reset`/`stash` | R4 no-orphan rule + backup discipline |
| MEDIUM | Two agents write the same file concurrently → corruption | R2/R3 checkout & branch isolation |
| MEDIUM | Force-push/delete of `main` by an agent | R1 blocks both |
| LOW | Branch clutter obscures real state | R1 auto-delete |

---

## 5. Remediation applied (2026-07-03)

- **R1 — Branch protection on `main`** *(enforced for everyone, incl. admins)*:
  require a PR, require the **`verify`** check green, **require the branch be up
  to date** before merge, block force-push, block deletion, require linear
  history. This structurally prevents C2/C3/C5 and the −500-line regression.
- **R1b — Auto-delete head branches on merge** enabled (fixes C4).
- **R2 — One canonical checkout:** `~/Fable` is the **only** sanctioned Reality
  working copy. The other two are to be retired (see §7).
- **R3 — Agent ownership & branch discipline:** see [AGENTS.md](../AGENTS.md) —
  one agent per checkout, one branch per unit of work, never commit to another
  agent's copy, never sit two copies on `main`.
- **R4 — No orphaned WIP:** every change is committed to a branch before a
  session ends; nothing is left uncommitted in a working tree.
- **R5 — CODEOWNERS** added so `src/game/` (the economy constitution) and
  `docs/` changes surface the right reviewer.
- **R6 — Stale branches deleted** (their content is already in `main`).

## 6. Go-forward workflow (the rule for every agent, including Claude)

```
1. git fetch && git switch -c <type>/<slug> origin/main   # branch off CURRENT main
2. …do the work…  (src/game/ stays pure; one sim path; immutable state)
3. npx vitest run && npm run build                        # must be green
4. git push -u origin <branch>  →  open PR
5. CI 'verify' passes + branch up to date  →  squash-merge  →  auto-deleted
```

`main` is now **merge-only**. No agent commits to `main` directly. Divergence is
impossible because every merge requires an up-to-date, CI-passing branch.

## 8. Incident 2 (2026-07-04): duplicate work on issue #27

Branch protection prevents *broken* merges; it does nothing about two agents
independently doing the *same* work. That's what happened: Claude and Codex
both built the "responsive pass" for issue #27 in parallel, unaware of each
other. Codex's PR (#39) merged first and closed #27; Claude's competing PR
(#40) then conflicted with the now-current `main` and was closed unmerged —
wasted, but not destructive, effort.

**A second lesson inside the same incident:** reviewing #39 from a static
screenshot led to an inaccurate claim (the mobile action bar looked
"unreachable/off-screen"). Re-tested properly in-browser — it's a horizontally
scrollable row, fully reachable by swipe. The *actual* bug found by rigorous
root-cause testing (bounding-box measurements, not eyeballing a screenshot) was
narrower: the Citizen card's name visually bled past its own HUD window and
got painted over by the next card. Fixed in PR #41.

**Remediation:** rule 3, "claim an issue before you start it," added to
[AGENTS.md](../AGENTS.md) — check for an existing assignee/branch/PR and
self-assign via `gh issue edit --add-assignee @me` before writing code. Also a
process note for reviewers: verify claims about a UI bug with real
measurements (`getBoundingClientRect`, computed styles) before asserting them,
not from a screenshot's first impression.
