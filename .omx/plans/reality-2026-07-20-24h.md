# Reality — 24-hour UX reliability plan (2026-07-20)

## Goal

Prove and harden the complete first-week loop in the built app: a new player can understand the first-session guide, open the local-day courier package, discover/gather deterministic resources, reach construction, recover from every blocker, and finish on an accessible recap that survives reload. Validate the experience with keyboard and a real assistive-technology-oriented audit without introducing new economy authority or dark-pattern retention mechanics.

- Main is clean at `83ac962` after PRs #1146 and #1148.
- The guide lifecycle is persisted as `startedAt`, `dismissed`, and `completedAt` in `src/store/gameStore.ts`, with migration tests in `src/store/migrateSave.test.ts`.
- First-session, map accessibility, and 320px smoke coverage exists in `e2e/first-session.spec.ts`, `e2e/map-accessibility.spec.ts`, and `e2e/mobile-smoke.spec.ts`.
- The audit still names two concrete risks: a full real-map resource/construction playthrough and manual VoiceOver/NVDA validation.

## 24-hour execution phases

### Phase 1 — Inspect and reproduce (hours 0–2)

Audit `WorldMap.tsx`, `mapAccessibleView.ts`, `CourierPackagePrompt.tsx`, `JourneyPanel.tsx`, `ConstructionPanel.tsx`, `constructionPanelView.ts`, `GoalsCard.tsx`, `FirstSessionGuide.tsx`, `MobileHud.tsx`, and `useFocusTrap`.

Record the actual state transitions and focus target for:

1. orientation dismissed;
2. food bought and used;
3. job selected and shift started;
4. courier package opened on the player’s local day;
5. fallback/resource node selected and gathered;
6. site placed, materials deposited, permit paid, labor assigned/worked;
7. recap opened and lifecycle completed.

Reproduce any dead end with a clean local save and with the deterministic fallback resource path.

### Phase 2 — Build an end-to-end first-week fixture (hours 2–7)

- Add a deterministic Playwright fixture or test helper that uses the real UI routes and only seeds bounded, documented state where waiting for real-time minutes would make the test non-deterministic.
- Prove courier opening, resource-node routing, resource deposit, construction placement, permit/labor blocker routing, and recap completion in one readable test journey.
- Assert that every transition changes the persisted save and that the next guide CTA changes accordingly.
- Keep the Market home-purchase flow unchanged.

### Phase 3 — Accessibility and focus audit (hours 7–12)

- Use Playwright accessibility assertions/snapshots for the guide, courier, resource groups, construction rows, blocker hints, dialogs, and recap.
- Verify keyboard-only order, Enter/Space activation, focus restoration after gather/Build navigation, Escape/back closure, and no focus trapped behind a drawer or non-modal sheet.
- Run a manual VoiceOver/NVDA-equivalent pass where available; document any environment limitation honestly.
- Fix only concrete issues: missing names/descriptions, incorrect live-region announcements, focus loss, insufficient touch targets, or unclear action copy.

### Phase 4 — Mobile and responsive hardening (hours 12–16)

- Test at 320×568 and a normal mobile viewport.
- Verify no horizontal overflow, readable blocker text, 44px-class touch targets, usable bottom sheets, and a visible primary CTA while activity banners or placement mode are active.
- Check reduced-motion behavior for guide and focus transitions.

### Phase 5 — Regression and release proof (hours 16–22)

Add focused tests for:

- local-day courier opening and repeat protection;
- fallback resource discovery and gather routing;
- material, permit, labor, and placement blockers;
- guide lifecycle migration, reload, and completion;
- accessible names, live status, keyboard activation, focus restoration;
- 320px first-week layout.

Run targeted tests, `npm run verify`, `npm run lint`, and `npm run test:e2e`.

### Phase 6 — Publish and continue (hours 22–24)

- Review the diff for scope creep, authority violations, and misleading engagement copy.
- Update `docs/AUDIT-2026-07-15.md` and `.omx/plans/autopilot-impl.md` with measured results and remaining risks.
- Commit with the Lore protocol, push a branch, open the normal PR, confirm CI and Vercel Preview, merge when required checks pass, and verify `main`.
- Identify the next unblocked tranche; do not enable payouts, withdrawals, crypto, land sales, settlement, automatic Founder Covenant enforcement, or client-authoritative economic state.

## Risks and mitigations

- **Real-time activity makes E2E slow/flaky:** seed only bounded fixture state; never add arbitrary sleeps or alter simulation duration.
- **Map data varies by environment:** use the existing deterministic fallback node path and assert its source is explained to the player.
- **Screen-reader tooling is unavailable:** use browser accessibility assertions, record the limitation, and keep manual review as the next tranche.
- **Onboarding becomes noisy:** keep one primary CTA, reuse existing panels, and prefer concise contextual copy.
- **Retention pressure drifts into dark patterns:** no artificial scarcity, loss framing, gambling, financial promises, or payout mechanics.
